# AGENTS.md

Guidance for coding agents working in this repository.

NACUT ("Not Another Claude Usage Tracker") is a menu bar / tray app for macOS, Windows and Linux. It reads Claude Code's
JSONL transcripts and the Claude Code sign-in to show plan limits (Max/Pro) or cost (API). One shared Rust core computes
every number; each platform has a native UI on top.

## Layout and how the pieces connect

```
core/      Cargo workspace: nacut-core (all logic), nacut-ffi (UniFFI cdylib/staticlib), nacut-cli (`nacut` binary)
shared/    Pricing.json (compiled into the core with include_str!) and test fixtures used by core tests and render mode
apple/     SwiftUI app + WidgetKit extension; links the core as an XCFramework through the NacutCore Swift package
windows/   WinUI 3 / .NET 10 C# app; loads nacut_ffi.dll through C# bindings generated by uniffi-bindgen-cs
linux/     GTK4 + libadwaita Rust app; depends on nacut-core directly (path dependency, no FFI)
```

- **`nacut-core::Engine`** (`core/nacut-core/src/engine.rs`) is what every app drives. It owns the history cache, watches
  transcript folders, runs scans / plan-limit fetches / Usage & Cost API refreshes on a background worker and timers,
  decides alerts, and answers UI queries (`snapshot`, `status`, `model_stats`, `sessions`, …). It is thread-safe; apps
  learn about changes through `EngineObserver::on_change` / `on_alert` (called on background threads) and re-read state.
- **`views.rs`** holds FFI-friendly precomputed view models so UIs only draw. **`ffi.rs`** (behind the `ffi` feature)
  wraps the engine as `NacutEngine` for UniFFI; the Linux app and the CLI use the plain Rust API.
- **`platform/`** is the OS-specific layer: data/config folders, Claude Code credentials (macOS Keychain item
  `Claude Code-credentials`, else `~/.claude/.credentials.json`), the `claude` CLI sign-in refresher (including
  `flatpak-spawn --host` inside Flatpak), the OS secret store for the API key (`keyring`), WSL discovery, file watching.
- **Settings:** Windows and Linux persist the core's `Settings` as JSON (`%APPDATA%\NACUT\settings.json`,
  `~/.config/nacut/settings.json`). The Mac app keeps settings in UserDefaults and maps them onto the core's `Settings`
  (`apple/App/AppSettings.swift`). An unparseable settings file is renamed to `settings.invalid.json`, never overwritten.
- **Mac widget:** the extension does not link Rust. The app writes a `WidgetSnapshot` JSON to
  `~/Library/Application Support/NACUT/` (`apple/Shared/WidgetSnapshot.swift`, shared by both targets) and the
  sandboxed widget reads it through a read-only temporary-exception entitlement.
- **Windows widget:** `WidgetProvider.cs` is a Widgets board COM provider with Adaptive Cards. It only exists in the
  packaged (MSIX) build, as do the toast activator and StartupTask (`Package.appxmanifest`).
- **Duplicated per-platform UI constants:** the palette and the fixed model → color-slot registry live in
  `apple/App/Views/Theme.swift`, `windows/NACUT/Theme.cs` and `linux/src/theme.rs`. Change all three together so a model
  keeps the same color on every platform. Each UI's tabs mirror the Mac's (Overview, Calendar, Models, Projects).

## Commands

Core (run from `core/`):

```bash
cargo test --workspace --locked                      # what CI runs on macOS, Linux, Windows x64 and Windows ARM64
cargo test -p nacut-core --test parity               # one integration test file (tests/parity.rs or tests/engine.rs)
cargo test -p nacut-core some_test_name              # a single test by name
cargo run -p nacut-cli -- summary --root ../shared/fixtures/proj   # CI smoke test
cargo run -p nacut-cli -- status --waybar            # also: limits, summary --json
```

`tests/parity.rs` is the old Swift `UsageCoreTests` suite ported with the same fixtures and expected values; keep it
passing when changing parsing, pricing or forecasts.

macOS (needs Xcode 26, XcodeGen, rustup):

```bash
apple/scripts/build-core.sh                          # core → apple/NacutCore/nacutFFI.xcframework + Swift bindings
cd apple && xcodegen generate                        # NACUT.xcodeproj is generated from project.yml (git-ignored)
xcodebuild -project NACUT.xcodeproj -scheme NACUT -configuration Release -derivedDataPath ../build/DerivedData -allowProvisioningUpdates build
```

Signing comes from `apple/Signing.xcconfig` (ad hoc by default), which includes an optional git-ignored
`apple/Local.xcconfig` with `DEVELOPMENT_TEAM` / `CODE_SIGN_IDENTITY`. Ad-hoc builds make macOS ask for Keychain access
again after every rebuild.

Windows (PowerShell; Rust, .NET 10 SDK, VS 2022 Build Tools; LLVM/clang on ARM64 for `ring`):

```powershell
windows\scripts\build-core.ps1 [-All]                # core DLL(s) → windows\NACUT\native\<Platform>, bindings → NACUT\Core\nacut.cs
cd windows\NACUT; dotnet build -c Release -p:Platform=ARM64   # or x64
windows\scripts\package.ps1 [-Platform x64] [-Install]        # signed MSIX (self-signed test cert unless NACUT_CERT_THUMBPRINT)
```

Linux (GTK 4.14+, libadwaita 1.5+):

```bash
(cd core && cargo build --release --locked -p nacut-cli)   # the .deb also ships the `nacut` CLI from core/target
cd linux && cargo build --release --locked && cargo deb --no-build
linux/flatpak/build.sh                                      # Flatpak on the GNOME 51 runtime
```

`linux/` is its own Cargo workspace (empty `[workspace]` in `linux/Cargo.toml`), separate from `core/`.

## Checking UI changes

Every app renders its views to PNGs without network, credentials, or touching real settings or the widget:

```bash
/Applications/NACUT.app/Contents/MacOS/NACUT --render-to /tmp/shots --limits-json shared/fixtures/limits-live.json
NACUT.exe --render-to C:\shots --limits-json shared\fixtures\limits-live.json
nacut-gtk --render-to /tmp/shots --limits-json shared/fixtures/limits-live.json
```

Render light and dark (Linux headless: `ADW_DEBUG_COLOR_SCHEME=prefer-dark GDK_BACKEND=x11 dbus-run-session -- xvfb-run nacut-gtk --render-to …`).

## Gotchas

- **UniFFI is pinned to `=0.28.3`.** `uniffi-bindgen-cs` must be the matching tag (`v0.9.2+v0.28.3`, set in
  `build-core.ps1`). After changing anything exported through `ffi.rs` or `views.rs`, regenerate both Swift
  (`build-core.sh`) and C# (`build-core.ps1`) bindings; the generated files are git-ignored.
- All Cargo builds use `--locked`; update `Cargo.lock` deliberately. CI actions are pinned to commit SHAs.
- `.github/workflows/ci.yml` is the only workflow that pushes and pull requests trigger; it calls the platform
  workflows for the paths that changed. `master` requires its `CI passed` check, so don't rename that job, and add any
  new build job to its change detection and to that job's `needs`.
- Settings files may start with a UTF-8 BOM (e.g. written by PowerShell); `Settings::parse` strips it.
- Rust's sum of an empty `f64` iterator is `-0.0`; percent formatting adds `+ 0.0` to avoid printing "-0%".
- Windows GUI processes must run in the interactive session; launched from SSH (session 0) they never appear. The panel
  hides on focus loss only after it actually had focus, because Windows can refuse foreground activation.
- New Windows tray icons start in the `^` overflow and apps can't promote themselves; the panel shows a tip
  (`TrayIcon.IsInOverflow` reads `HKCU\Control Panel\NotifyIconSettings`).
- GNOME on Wayland doesn't let apps position windows; the tray needs the AppIndicator extension (built into Ubuntu).
- Transcript message text is never decoded or stored: only model, token counts, timestamps, project folder, session ID
  and entry point. Everything the app sends goes to `api.anthropic.com` (see README "Privacy and security"); don't add
  telemetry or third-party endpoints.
